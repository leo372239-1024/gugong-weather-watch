# 故宫天气守望

每天北京时间 **07:00** 自动巡检，服务于两件事：

| 任务 | 判定 | 通知渠道 |
|---|---|---|
| **A. 降雪预警** | 未来 8 天内是否有雪 → 倒推故宫抢票时刻 | 邮件 |
| **B. 每日天气播报** | 每天必推（默认）→ 天气、概率、气温、穿衣建议 | Bark 推送到 iPhone |

两个任务互相独立，任一失败不影响另一个。天气位置统一为**北京故宫博物院**（39.9163°N, 116.3972°E）。

部署在腾讯云 CloudBase 云函数，无需常驻服务器，纯 Python 标准库零依赖。

## 一、任务 A：降雪预警为什么这样做才「尽可能准确」

单一数据源判断降雪极易翻车。本项目采用气象业务中标准的**集合预报 + 多模式集成**方法：

| 层次 | 做法 | 作用 |
|---|---|---|
| 集合预报概率 | ECMWF IFS **50 个成员**，统计报出降雪的成员比例 | 「会不会下」最严谨的量化方式，直接给出概率 |
| 确定性多模式投票 | ECMWF / GFS / ICON / **CMA-GRAPES（中国气象局）** / JMA / GEM 共 6 家 | 交叉验证，避免单一模式系统性偏差 |
| 相态校验 | 取**报雪那几家模式**的日最低温中位数二次判断 | 北京冬季 0~3℃ 常是雨夹雪，需剔除「模式报雪但落地是雨」 |
| 硬性物理约束 | 最低温 ≥ 3.5℃ 直接排除降雪 | 暖天降水不可能成雪 |

**置信度分级**：高 = 集合概率 ≥50% 或 ≥4/6 模式报雪；中 = ≥25% 或 ≥2/6；低 = >5% 或 ≥1/6。

相态修正：报雪模式最低温 ≥2.5℃ 连降两级并标注「可能为雨夹雪」；最高温 ≤0℃ 升一级并标注「积雪易留存」。

## 二、任务 A：抢票时间推算

故宫官方规则（已核验 [ticket.dpm.org.cn](https://ticket.dpm.org.cn/)）：门票**参观日前 7 天 20:00** 开售，**不售当日票**，**周一闭馆**（法定节假日除外）。

若雪日为 `D+n`，抢票日为 `D+n-7`。程序扫描 15 天，告警聚焦最近 8 天——8 天窗口恰好覆盖「今晚可抢」的边界：

| 雪日 | 抢票日 | 邮件提示 |
|---|---|---|
| 今天 + 7 天 | 就是**今天** | 🔴 就在今晚 20:00 开抢 |
| 今天 + 8~15 天 | 未来 1~8 天 | 🟠 N 天后开抢，先记日历 |
| 今天 + 6 天内 | 已过 | ⚪ 预售已开，只能看余票/退票回流 |

雪日撞上周一，邮件额外提示闭馆。

## 三、任务 B：每日天气播报

### 为什么不用短信

国内**没有合规且永久免费的 SMS 通道**。运营商按条计费（腾讯云/阿里云约 0.045 元/条），且个人主体申请短信签名通常需 APP/网站备案资质，通知类模板另需逐条审核；所谓「免费额度」多为新用户一次性 50~100 条试用。

因此改用 **Bark**：开源 iOS 推送服务，App Store 免费无内购，公共服务器不限量，通知经 Apple APNs 直达 iPhone 锁屏，并支持「时效性通知」等级（可突破专注模式），实际提醒强度接近短信。

- 官方站点：<https://bark.day.app/>
- 服务端源码：<https://github.com/Finb/bark-server>
- 自建可改 `BARK_SERVER`，不依赖公共服务

### 触发规则（每天必推一条）

| 情况 | 是否推送 |
|---|---|
| 当天为多云 / 阴 / 雾 / 雨 / 雪 / 雷暴 | ✅ 推送 |
| 当天为晴，但降水概率 ≥ 50% | ✅ 推送（防止「预报说晴却下雨」） |
| 当天为晴且降水概率 < 50% | ✅ 推送（默认每日必推） |

> **变更记录（2026-10-30）**：早期版本对「晴天且降水概率低」直接静默。10-29、10-30 北京连续晴天，
> 云函数两次都成功执行却零通知，观感上等同服务挂了。逐条核对云端日志（触发器准时、函数 4.7~6.6 秒
> 成功返回、Bark 通道前一日推送正常）后确认不是故障，而是规则导致的「设计性静默」。
> 提醒类服务的核心价值是**稳定出现**，不是省一条通知，故默认改为每日必推。
>
> 如需恢复安静模式（晴天不打扰），把环境变量 `BRIEF_ALWAYS_PUSH` 设为 `false` 即可。

### 只看白天活动时段（07:00–21:00）

穿衣建议**不使用全天极值**。原因很实际：北京秋冬凌晨最低温常在 0℃ 附近，若按全天极值判断会建议「羽绒服」，而白天 12℃ 根本穿不住。

程序因此额外拉取小时级数据，两个窗口刻意分开：

| 指标 | 窗口 | 理由 |
|---|---|---|
| 体感温度、气温、风速 | **07:00–21:00** | 用户主要在外活动的时间，用于穿衣分档 |
| 降水概率 | **07:00–24:00** | 按需求覆盖到当天结束（23 点数据代表 23–24 时段） |

### 穿衣分档（按 07:00–21:00 体感最低温）

| 档位 | 体感温度 | 上衣（内搭 + 中层 + 外套） | 下衣 | 鞋子 | 袜子 |
|---|---|---|---|---|---|
| 极寒 | < -10℃ | 加厚发热内衣 + 羊毛衫/抓绒衣 + 长款加厚羽绒服/派克大衣 | 防风裤/加绒裤 | 高帮雪地靴或厚底防水登山鞋 | 加厚羊毛袜（务必包裹脚踝） |
| 严寒 | -10 ~ 0℃ | 加厚发热内衣 + 羊毛衫/抓绒衣 + 厚羽绒服/长款棉服 | 常规长裤（户外配防风裤） | 加绒短靴或高帮马丁靴 | 中厚羊毛袜 |
| 严冬 | 0 ~ 5℃ | 发热内衣/美利奴打底 + 厚毛衣/羽绒马甲 + 防风大衣/羽绒服/冲锋衣 | 防风裤/休闲长裤 | 皮质短靴或加绒休闲鞋 | 厚棉袜或薄羊毛袜 |
| 深秋/初冬 | 5 ~ 10℃ | 高领打底/长袖T恤 + 针织马甲/薄卫衣 + 毛呢大衣/短风衣 | 休闲裤/牛仔裤 | 乐福鞋、切尔西靴或帆布鞋 | 中厚棉袜 |
| 春秋过渡 | 10 ~ 15℃ | 长袖T恤/衬衫 + 薄针织开衫/卫衣 + 薄风衣/夹克 | 运动裤/牛仔裤 | 运动鞋、板鞋或单皮鞋 | 标准厚度棉袜 |
| 温暖舒适 | 15 ~ 20℃ | 短袖T恤/衬衫 + 薄外套（防晒衣/开衫，可选） | 透气长裤/短裤 | 网面运动鞋、凉鞋或休闲鞋 | 薄棉袜或隐形袜 |
| 夏季 | ≥ 20℃ | 短袖T恤（注重透气与防晒） | 短裤/轻薄长裤 | 透气运动鞋、拖鞋或凉鞋 | 薄袜或不穿袜 |

### 风力与空气质量

- **风力**：白天风速区间按蒲福风级换算成「X~Y级」，再叠加阵风级别。风向取主导风向，折算八方位中文（北风/东北风/…）。
- **空气质量**：Open-Meteo 只给美标（us_aqi）与欧标（european_aqi），与中国 AQI 分档不同。程序取白天 PM2.5 / PM10 均值，按《环境空气质量指数(AQI)技术规定》**HJ 633-2012** 分段线性插值折算国标 AQI，两者取大者，再映射到优/良/轻度污染等六级。

### 推送样例（2026-10-28 真实数据）

```
⛅ 今日天气简报
【晴转多云  下雨概率0%】
1.气温范围：3℃ ~ 14℃
2.风力风向：西南风0~2级，阵风4级
3.空气质量：130（轻度污染）
4.穿衣建议：
①季节：严冬
②上衣建议：发热内衣/美利奴打底 + 厚毛衣/羽绒马甲 + 防风大衣/羽绒服/冲锋衣
③下衣建议：防风裤/休闲长裤
④鞋子建议：皮质短靴或加绒休闲鞋
⑤袜子建议：厚棉袜或薄羊毛袜
5.日期：2026年10月28日（星期三）
```

- 标题图标随天气变化（☀️/⛅/☁️/🌧️/🌨️/🌫️），取**下午**天气类别，与「A转B」文案呼应
- 「晴转多云」这类描述：分别取上午 10 点与下午 17 点的天气现象，类别不同则写「A转B」
- 概率标签随天气变化：雨天「降水概率」、雪天「降雪概率」、其余「下雨概率」
- 穿衣建议拆为 5 个子项（季节/上衣/下衣/鞋子/袜子），便于逐项对照
- 若有模式分歧，末尾追加一行告警：主源（best_match）与 ECMWF 判断不一致时如实标注，不假装确定

## 五、部署信息

| 项 | 值 |
|---|---|
| 云平台 | 腾讯云 CloudBase |
| 环境 ID | `your-env-id`（替换为你自己的 CloudBase 环境） |
| 函数名 | `gugong-snow-alert`（沿用此名可免改云函数入口） |
| 运行时 | Python 3.10 |
| 入口 | `index.main`（兼容 `index.main_handler`） |
| 超时 / 内存 | 120 秒 / 256 MB |
| 定时触发器 | `daily-0700`，cron `0 0 7 * * * *`（**北京时间 07:00**，已实测） |
| 日志 | 已开通 CLS，按 `requestId` 可查每次执行全过程 |

**关于 cron 时区（实测结论，非文档推断）**

官方文档只说明入参 `Time` 是 0 时区，未明确 cron 按哪个时区解析。做了对照实验：

- `0 6 10 * * * *`（若按 UTC，应在北京 18:06 触发）→ **未触发**
- `0 9 18 * * * *`（若按北京，应在 18:09 触发）→ **18:09:04 准时触发**

结论：**CloudBase 定时触发器 cron 按北京时间（UTC+8）解析**。

## 七、故障处理

- **天气抓取失败**：重试 3 次（间隔 3/8/20 秒）；仍失败则任务 A 发红色告警邮件说明「今天没有结论」，**不静默跳过**。
- **邮件失败**：重试 3 次后抛出，云函数记一次失败。
- **Bark 失败**：v2 接口失败自动回退 v1 接口，共重试 3 次。
- **单任务失败**：另一任务照常执行，最终抛出的异常会列出两侧状态，便于定位。
- **无雪**：静默，不发邮件（天气播报照常推送）。

## 八、已知限制

1. Open-Meteo 网格会归到最近格点（约 4km 外），能代表故宫一带，但无法区分太和殿前与景山。
2. 8 天以上降雪预报存在固有漂移，程序如实标注置信度而非假装确定。
3. 穿衣分档是基于体感温度的通用规则，未考虑个人耐寒差异与室内外温差。
4. Bark 通知需要 iPhone 允许 Bark 的通知权限；若开启「专注模式」，需把 Bark 加入允许列表或依赖时效性通知等级。
5. 故宫未授权任何第三方代理售票，官方渠道仅「故宫博物院」小程序 / ticket.dpm.org.cn。
